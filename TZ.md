# Техническое задание: интернет-магазин цветов "Bloom"

## 1. О проекте

Небольшой цветочный магазин без собственного отдела разработки. Нужен сайт-каталог с возможностью онлайн-заказа и админ-панелью, чтобы владелец мог **самостоятельно** добавлять, редактировать и убирать товары без участия программиста.

## 2. Целевая аудитория

Частные покупатели 20–45 лет, заказывающие букеты и композиции к событиям (дни рождения, свадьбы, праздники) через телефон или ноутбук. Основной канал перехода — мобильный (ожидается 65–70% трафика с телефонов).

## 3. Технический стек

| Слой | Технология |
|---|---|
| Frontend | Next.js (React) |
| Стили | Tailwind CSS |
| База данных | PostgreSQL (Neon / Vercel Postgres, бесплатный тариф) |
| Хостинг | Vercel |
| Домен | покупается заказчиком отдельно, подключается на этапе сдачи |

## 4. Функциональные требования — публичная часть

- **Главная страница** — баннер/акции, ссылка на каталог, категории товаров
- **Каталог** — сетка товаров с фильтром по категориям (букеты, горшечные растения, композиции, подарки) и сортировкой по цене
- **Карточка товара** — фото, название, цена, описание, статус наличия ("в наличии" / "под заказ"), кнопка "добавить в корзину"
- **Корзина** — список выбранных товаров, изменение количества, удаление позиции, итоговая сумма
- **Оформление заказа** — форма: имя, телефон, адрес доставки, дата/время, комментарий
- **Оплата онлайн** — имитация процесса оплаты картой (форма ввода карты → "Оплата успешна") без реального подключения к платёжному сервису. Также остаётся вариант "оплата при получении"
- **Страница "О нас" и "Контакты"** — адрес, телефон, карта, режим работы
- Заказ после отправки сохраняется в базу данных и появляется в админ-панели

## 5. Функциональные требования — админ-панель

- Вход по логину/паролю (одна учётная запись — владелец магазина)
- CRUD-управление товарами: добавить / редактировать / удалить, загрузка фото, изменение цены и статуса наличия
- Управление категориями
- Список поступивших заказов с контактами клиента, статус заказа ("новый" / "в работе" / "выполнен")

## 6. Вне рамок проекта (явно не делаем)

- Интеграция с 1С или другими учётными системами
- Мультиязычность
- Push/email-уведомления о статусе заказа
- Программа лояльности/бонусы

> **Важная оговорка по оплате:** на этом этапе оплата картой имитируется в интерфейсе, реального платёжного сервиса не подключаем. Когда понадобится реальный приём денег — подключается платёжный сервис (например, ЮKassa) сначала в тестовом режиме (бесплатная регистрация, без документов), а затем в боевом — после того как владелец магазина оформит ИП/ООО и пройдёт проверку. Это отдельный шаг, не блокирующий текущую разработку.

## 7. Нефункциональные требования

- **Адаптивность** — корректное отображение и удобство на экранах от 360px (мобильные) до 1920px
- **Скорость загрузки** — Lighthouse Performance ≥ 90 на мобильной версии
- **Базовое SEO** — заполненные title/description на каждой странице, семантическая разметка, alt-теги у изображений
- **Доступность** — читаемый контраст текста, видимый фокус на интерактивных элементах, работоспособность без мыши (клавиатурная навигация)

## 8. Хостинг и деплой

- Код разворачивается на Vercel (бесплатный тариф)
- База данных — облачный Postgres с бесплатным тарифом (Neon/Vercel Postgres)
- Домен покупает и оплачивает заказчик, привязка (DNS) — на стороне исполнителя при сдаче проекта

## 9. Что предоставляет заказчик

- Фотографии товаров (или используются временные/стоковые на этапе разработки)
- Тексты для разделов "О нас" и "Контакты"
- Логотип (или согласуется временный на этапе разработки)
- Цены и перечень стартового ассортимента

## 10. Критерии приёмки

- Все страницы из п.4 реализованы и работают на мобильном и десктопе
- Владелец может самостоятельно добавить/изменить/удалить товар через админ-панель без помощи разработчика
- Оформленный заказ сохраняется в базе и виден в админ-панели
- Сайт задеплоен на Vercel и доступен по рабочей ссылке
